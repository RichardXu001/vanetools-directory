VaneTools: a curated directory of 38,182 AI resources — with the open data to prove it

VaneTools is a bilingual (English/中文) AI directory covering 38,182 curated resources — 22,733 AI apps, 6,170 prompts, 4,893 skills, 3,082 plugins, 989 workflows, 278 MCP servers and 37 learning resources. Every listing is editorially reviewed and links to a detail page with the project's official site, so agents and humans can verify sources instead of guessing tool names.

This site is the open-data companion to vanetools.com: it documents the full catalog index (tools/), the public MCP endpoint for AI agents (connect/), and answers common questions (faq/). Everything here ships from the open repository RichardXu001/vanetools-directory, MIT licensed.

Three ways to use the catalog

🌐 Browse online

Search and browse everything on vanetools.com — bilingual detail pages, categories, continuous additions.

🤖 Query from your AI agent

Point any MCP client (Claude, Cursor, VS Code) at the public endpoint — 30-second setup, no API key required.

📦 Take the data

Download the whole index as one JSON file (MIT) — names, types, URLs, official websites.

For AI agents: the MCP endpoint

VaneTools also runs a remote MCP server so your agent can search the live catalog in natural language — “find MCP servers for Postgres”, “recommend open-source AI image upscalers”. The endpoint is public, read-only and needs no authentication:

{
  "mcpServers": {
    "vanetools": {
      "url": "https://vanetools.com/mcp"
    }
  }
}

Step-by-step instructions for Claude Desktop, Cursor and VS Code are in the connection guide; the server is listed in the official MCP Registry as com.vanetools/vanetools-directory.

Why open data?

Because a directory is only as trustworthy as its data. The full index is published as catalog.json (MIT), regenerated deterministically from the public llms-full.txt feed — the same data agents get over MCP. Metadata only: names, types, URLs, official sites. Descriptions stay on the detail pages so the two never drift. Common questions are answered on the FAQ page.
